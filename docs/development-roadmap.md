# 小明智能投保助手 V2.0 开发路线

状态：已冻结为实施基线

产品：复星联合达尔文 12 号重大疾病保险（互联网）

产品 ID：36743
首期形态：保险顾问使用的单产品、限定域、内部 POC

## 1. 不可变业务边界

目标产品只覆盖九类能力：保障责任、免责与限制、投保规则、职业查询、投保流程、动态资料清单、健康告知、理赔路径和正式投保外链。

POC 不做：

- 其他产品推荐、比较或通用保险百科；
- 真实保费试算、报价、支付、保单查询、保全、续期和退保；
- 核保、承保、拒保、加费、除外、医学诊断或治疗结论；
- 真实理赔入口、进度和赔付结论；
- 自动代填、提交投保或回传承保结果。

关键结论必须有正式资料证据；关键数字必须由结构化规则返回；证据不足或冲突时停止给出确定结论。

## 2. 阶段总览

### Phase 00：开发基线

分支：`phase/00-development-baseline`

范围：

- 固化 V2.0 文档、用户补充决策和需求优先级；
- 建立 VS Code、Java 21、环境变量和本地启动配置；
- 建立分支、标签、验收报告和阶段门禁；
- 验证 Key 不进入 Git；
- 完成现有基线的编译与测试调查，记录旧代码和目标产品的差距；
- 禁止实现任何 V2.0 业务功能。

退出条件：开发环境可复现；仓库干净；阶段门禁可运行；Phase 00 报告为 PASS。

### Phase 01：工程骨架与统一契约

分支：`phase/01-foundation-contracts`

范围：Vue 3 + TypeScript + Vite + Pinia + Vue Router H5 骨架；Spring Boot `/api/v1/xiaoming` 骨架；ProductContext；九类意图枚举；统一响应、错误码、traceId、requestId、幂等接口契约；本地 H2 配置；健康检查。

退出条件：前后端构建通过；OpenAPI/类型契约一致；所有状态和错误码有契约测试；页面在五档宽度无布局缺陷。

### Phase 02：知识版本、规则与证据底座

分支：`phase/02-knowledge-rules-evidence`

范围：产品与知识版本模型；资料状态；页码映射；语义切分；BM25、Embedding、RRF；结构化规则条件树；EvidenceService；证据门禁；检索降级和冲突停止。

退出条件：版本隔离、RRF、页码、规则、证据完整性和依赖故障测试全部通过。

### Phase 03：核心问答与限定域安全

分支：`phase/03-core-conversation-guardrails`

范围：保障责任、免责、投保规则、投保流程、理赔路径；最少追问；九类白名单；混合问题拆分；提示注入防护；结构化卡片与依据面板。

退出条件：范围内标准题通过；超范围与注入测试 100% 拒答；关键数字与规则一致；无依据不生成结论。

### Phase 04：职业查询

分支：`phase/04-occupation`

范围：职业标准化、候选搜索、最多五项、occupationId 确认、版本化职业表和未命中处理。

退出条件：确认前不判断；确认后精确查询；别名、多候选、未命中、多职业和超时测试通过；P95 目标可测。

### Phase 05：会话历史与动态资料清单

分支：`phase/05-history-checklist`

范围：IndexedDB、schemaVersion、会话原子保存、新建/恢复/改名/删除、客户隔离、动态清单、勾选持久化和版本更新提示。

退出条件：刷新、返回、删除、迁移失败和存储失败不串客户、不丢原会话；共享设备风险提示存在。

### Phase 06：健康告知三态流程

分支：`phase/06-health-disclosure`

范围：授权、文件校验、文字/PDF/JPG/PNG、事实提取、来源定位、人工确认、HIT/NO_HIT_FOUND/INSUFFICIENT、临时文件清理和隐私保护。

退出条件：未确认不匹配；只输出三态；模拟命中、未发现、信息不足、否定语义、时间窗、单位、OCR/上传失败和敏感日志测试通过。

### Phase 07：正式投保外链与反馈

分支：`phase/07-application-feedback`

范围：投保前检查、安全外链、域名与参数白名单、环境隔离、生产不回退 UAT、脱敏反馈和受限埋点。

退出条件：未知参数丢弃；健康/客户信息不进入 URL；未配置生产地址明确停止；外链、反馈和日志安全测试通过。

### Phase 08：POC 全链路验收

分支：`phase/08-poc-hardening`

范围：30—50 道标准题、九类 E2E、故障注入、性能、响应式、可访问性、隐私、演示脚本和回归。

退出条件：PRD AC-01 至 AC-10、前后端 Definition of Done 和后端 Definition of Done 全部通过；业务负责人验收后才允许讨论生产化。

## 3. 阶段验收流程

每个阶段按以下顺序执行：

1. 冻结本阶段范围和验收清单。
2. 开发并同步更新测试、接口契约和文档。
3. 执行 `scripts/phase-gate.sh`。
4. 执行阶段特有的 API、浏览器、E2E、安全和故障测试。
5. 创建 `docs/acceptance/phase-NN-report.md`，逐项记录命令、结果和证据。
6. 任一必测项失败：修复后完整重跑，不能跳过。
7. 全部通过：提交、创建 `phase-NN-passed` 标签，再创建下一阶段分支。

## 4. 用户参与点

只有以下事项必须交还用户：

- 在 `.env.local` 输入或更换真实 API Key；
- 提供正式产品资料、职业表、健康告知、规则和标准答案；
- 确认正式投保 UAT/生产地址以及允许域名；
- 完成业务、合规和生产上线审批；
- 提供自己的 GitHub/GitLab 远程仓库，供云端备份和 Codex Cloud 使用。

其他开发、测试、失败排查、回归和阶段报告由开发代理完成。
