# Phase 05 验收清单：会话历史与动态资料清单

状态：验收通过（PASS）

分支：`phase/05-history-checklist`

## 1. 本阶段范围

- 使用 IndexedDB 保存会话、消息、结构化上下文、知识版本、清单和偏好，数据库携带 `schemaVersion`。
- 会话切换前以一个事务原子保存消息、上下文、知识版本和清单；失败时不切换、不删除原会话。
- 支持首次自动创建、刷新恢复最近会话、新建客户、搜索历史、恢复、继续、修改非敏感备注和单条删除。
- 新建客户先保存旧咨询，再创建全新上下文；取消或保存失败时继续留在原会话。
- 历史回答保留原知识版本；当前版本变化时提示可按最新资料重新查询或重新生成清单。
- 动态清单按年龄、投保关系、证件类型、受益人设置和健康状态生成，分为需录入信息、需准备材料、需阅读确认文件。
- 清单明确区分必需项和建议项；勾选只属于当前客户会话并立即持久化。
- 支持只看未完成项；“重新生成”放入低频菜单，覆盖前二次确认，取消保留原清单与勾选。
- 显著提示本机历史与共享设备风险，并提供导出和清空全部本机数据入口。

## 2. 明确不做

- 不把浏览器历史同步到服务端，不建立顾问登录；生产仍计划使用邀请码准入。
- 不保存真实身份证号、手机号、完整病历、原始健康文件或完整健康事实。
- 不因健康状态生成补件规则；只提示正式投保时如实完成健康告知。
- 不调用 DeepSeek 生成资料清单，不把客户上下文发送到外部模型。
- 不提前实现健康文件上传、健康三态匹配、正式投保地址或投保状态回传。

## 3. IndexedDB 与会话门禁

- 数据库包含 conversations、messages、checklists、healthFacts 和 preferences，升级由 `schemaVersion` 控制。
- 迁移事务失败必须保留旧库，页面提示重试、导出或清理，不静默删除数据库。
- 会话保存、切换、新建、恢复、改名和删除覆盖成功、取消、存储失败与重试。
- 单条删除必须二次确认；取消零变更；删除当前会话后恢复其他会话或创建安全空会话。
- 客户 A/B 的消息、上下文、职业确认与清单不得互串；刷新、返回和恢复后仍保持隔离。
- 备注拒绝明显身份证号或手机号样式，限制长度，错误监控和控制台不得记录备注或消息正文。
- 清空全部本机数据必须二次确认，成功后清理 IndexedDB 与内存 Store，并明确不可恢复。

## 4. 动态资料清单门禁

- `POST /api/v1/xiaoming/checklists/generate` 只使用当前产品和当前 PUBLISHED 知识版本。
- 请求字段白名单、必填条件、年龄范围、枚举值、版本冲突、空快照和幂等冲突有明确安全结果。
- 相同请求与幂等键重试结果一致；同键不同请求拒绝。
- 未成年人、非本人投保、非居民身份证、指定受益人和需健康告知场景生成预期差异项。
- 健康异常只增加“正式投保时如实告知”提示，不生成诊断、核保结论或补件材料。
- 响应携带清单规则版本和知识版本，不包含客户身份数据或正式投保地址。
- 勾选保存失败时回滚界面；刷新、恢复其他客户再返回时，原勾选状态准确恢复。

## 5. 前端、响应式与可访问性

- 顶部提供历史咨询和新建客户入口，显示当前非敏感备注；历史在桌面使用侧抽屉。
- 新建、删除、清空和覆盖弹层具备焦点锁定、Esc/返回取消、主辅操作和焦点归还。
- 历史搜索、空态、加载、成功、失败、迁移失败、存储失败和知识版本更新提示均可恢复。
- 375、390、430、768、1440 px 无溢出、遮挡或不可达操作；触控目标不小于 44 px。
- Tab 顺序、3 px 可见焦点、语义标题/列表/表单、`aria-live` 和 reduced-motion 检查通过。
- 页面仍明确 POC 免登录、正式上线邀请码准入、共享设备风险和不要输入敏感信息。
