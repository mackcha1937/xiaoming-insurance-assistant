# Phase 08 验收清单：POC 全链路加固

状态：技术门禁、一次真实模型最小 E2E 及标准题业务确认通过；人工设备项待完成

分支：`phase/08-poc-hardening`

依据：V2.0 PRD、前端开发文档、后端开发文档、项目立项报告及 `docs/development-roadmap.md`。

## 1. 本阶段范围

- 建立 30—50 道可版本化标准题集，覆盖九类限定域、口语改写、边界问题、规则数字、证据和预期业务状态。
- 建立九类全链路 E2E、主动作全状态、历史恢复、版本更新、客户隔离、健康确认和安全外链回归。
- 覆盖模型、OCR、BM25、向量库、配置、网络、限流和临时存储故障；验证安全降级与停止条件。
- 验证职业搜索 P95≤2 秒、普通问答 P95≤8 秒、健康解析 30 秒超时目标，并记录样本、环境和统计口径。
- 完成 375、390、430、768、1440 px、长文本、系统大字体、减少动态效果、键盘和自动可访问性检查。
- 完成提示注入、文件内指令、恶意文件名/类型、XSS、未知外链、敏感日志、幂等、重复点击和限流检查。
- 生成内部演示脚本、已知限制、运行手册和最终 POC 验收报告。

## 2. 明确不做

- 不实现生产邀请码、顾问登录、权限、服务端健康数据持久化、运营后台或生产发布。
- 不接入未由用户确认的真实 UAT/生产地址，不把保留域名或测试夹具描述为真实环境验收。
- 不使用模型常识补齐缺失证据，不生成核保、医疗、承保或实际赔付结论。
- 不以自动化测试替代业务负责人对标准问题、答案和正式资料口径的最终签字。

## 3. PRD AC-01～AC-10

- `AC-01`：九类白名单主链路全部闭环。
- `AC-02`：所有关键回答均可查看有效依据。
- `AC-03`：关键数字与结构化规则一致并可追到 `ruleId`。
- `AC-04`：职业确认前不判断，确认后严格查询当前职业表。
- `AC-05`：健康事实确认后才匹配，且只输出三态。
- `AC-06`：新建客户后旧会话保留，客户上下文不串用。
- `AC-07`：每个按钮具备成功、取消、失败和重试/返回闭环。
- `AC-08`：超范围题 100% 拒答，不输出核保、医疗或真实理赔结论。
- `AC-09`：production 没有批准地址时明确停止，绝不回退 UAT。
- `AC-10`：30—50 道标准问题通过自动回归，并由业务负责人确认标准答案。

## 4. 标准题集门禁

- 题集使用机器可读格式，固定 `caseId`、产品、意图、问题、预期状态、关键断言、禁止内容、预期证据/规则和知识版本。
- 总数 30—50；九类能力每类至少 3 道，另含不少于 8 道超范围/注入/混合问题。
- 至少覆盖关键词问法、自然口语改写、错别字/空白/全半角、混合可答与不可答、关键数字边界。
- 确定性断言不得依赖模型措辞；规则数字比较结构化结果，证据比较正式资料 ID/页码/片段。
- 题集和运行结果不得包含真实客户、身份、联系方式、健康文件或生产 URL。
- 任何标准题失败都必须定位为题库、知识、规则、检索、生成或输出门禁问题；不得降低断言绕过。

## 5. 九类 E2E 与按钮闭环

- 保障责任、免责与限制、投保规则、职业查询、投保流程、动态资料清单、健康告知、理赔路径、正式投保均从页面入口完成主链路。
- 每个写操作验证 requestId/Idempotency-Key；失败重试必须沿用同一标识，同键异体必须拒绝。
- 所有关键动作覆盖默认、禁用、处理中、成功、取消、失败和重试/返回；单卡不超过一个主按钮和一个辅助按钮。
- 刷新、浏览器返回、网络中断、历史恢复、新建/切换/删除客户、知识版本更新不丢输入、不串客户。
- 投保外链验证未配置停止、成功确认、取消、过期、弹窗拦截、复制、未知域名和 production/UAT 隔离。

## 6. 故障、降级与安全

- 模型失败/超时：保留输入，允许同幂等键重试，不生成猜测答案。
- BM25 失败：关键回答安全停止；向量失败可降级 BM25，但仍经过证据门禁并标记降级。
- OCR/健康解析失败或 30 秒超时：保留授权边界，允许手工输入，不保存原文件或半成品。
- 配置、知识版本、职业表、健康问题版本或投保域名缺失/冲突：相关功能关闭并返回明确错误，不带病启动或回退旧环境。
- 临时存储和 IndexedDB 失败：页面可理解、原会话不丢、不同客户不串用。
- 覆盖提示注入、文件内指令、恶意扩展名/MIME/文件名、XSS、开放重定向、敏感日志和限流。

## 7. 非功能门禁

- 性能：职业搜索 P95≤2 秒；普通问答 P95≤8 秒；健康解析 30 秒超时并可手工输入。报告必须记录样本量、预热、硬件、profile 和 P50/P95/max。
- 响应式：375、390、430、768、1440 px 无横向溢出、遮挡、文本撑破或不可达动作；375—430 单列，≥768 内容居中。
- 可访问性：触控≥44 px、焦点可见、Tab 顺序、弹层锁定/Escape/归还、可访问名称、文字+图形状态、减少动态效果和自动检查通过。
- 隐私：浏览器、服务端日志、异常、指标、导出、测试报告均不含正文、客户备注、健康事实、原文件或正式投保完整 URL。
- 兼容性：基于可用浏览器环境完成 Chromium 桌面/移动仿真；真实 iOS/Android 设备验证如无法自动执行，必须明确列为人工项。

## 8. 前端 Definition of Done

- 无卡片超过一个主按钮和一个辅助按钮。
- 所有点击动作覆盖默认、禁用、处理中、成功、失败和取消。
- 刷新、返回、网络中断不会造成跨客户串数据。
- 所有接口错误映射到可理解页面状态。
- 无障碍、响应式、隐私日志和九类端到端测试全部通过。

## 9. 后端 Definition of Done

- 九类意图和统一响应契约稳定，前端无需解析文本生成动作。
- 所有确定性数字由规则返回并带 `ruleId`；关键答案证据可追溯。
- 健康未经确认不匹配，且只输出三态。
- production 不可能自动使用 UAT 投保地址。
- 日志、错误监控和指标通过敏感信息检查。
- 标准题、注入、故障、幂等和接口契约测试全部通过。

## 10. 阶段退出条件

- `scripts/phase-gate.sh`、标准题、九类 E2E、故障、安全、性能、响应式、可访问性和范围审计全部通过。
- 生成 `docs/acceptance/phase-08-report.md`、标准题执行结果、演示脚本和已知限制；自动化结论真实可复现。
- 用户/业务负责人完成标准题答案与产品口径确认。未确认时阶段保持“技术验收通过、业务验收待确认”，不得宣称最终 POC PASS。
- 真实移动设备、UAT 或生产环境若未提供，报告必须明确未验收；测试夹具不得冒充真实验收。
- 只有所有必需项通过且业务负责人确认后，Phase 08 才能标记 `PASS`；否则不得创建生产化分支或标签。
