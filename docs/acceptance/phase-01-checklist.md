# Phase 01 验收清单：工程骨架与统一契约

状态：`PASS`（2026-08-27）

分支：`phase/01-foundation-contracts`

## 1. 本阶段范围

- 建立 Vue 3、TypeScript、Vite、Pinia、Vue Router 的独立 H5 工程骨架。
- 建立 Spring Boot `/api/v1/xiaoming` 接口骨架。
- 固定产品上下文：产品 ID `36743`、产品名称、知识版本和环境。
- 固定九类意图、六种业务状态、统一响应、统一错误、traceId 和 requestId。
- 为写请求建立 `Idempotency-Key` 契约和可回归的幂等占位实现。
- 提供无需登录的产品上下文、readiness 和 chat 占位接口；chat 不调用模型、不生成业务结论。
- 保持旧车险 POC 接口和测试可回归，不把它们当作 V2.0 实现。

## 2. 明确不做

- 不实现 Phase 02 的知识版本发布、RAG、RRF、规则或证据门禁。
- 不实现 Phase 03—07 的真实问答、职业、历史、资料清单、健康或投保外链。
- 不调用真实 DeepSeek，不执行付费 E2E。
- 不增加登录；POC 免登录，生产邀请码准入留在生产化阶段。
- 不删除或大规模改写旧车险 POC。

## 3. 必须通过的后端检查

- Java 21 编译通过，旧测试全量回归通过。
- 产品上下文和 readiness 正常、字段完整、无需认证。
- chat 占位接口稳定返回明确的未就绪错误，不返回半成品业务结论。
- 九类意图、六种状态和全部 V2.0 错误码与共享契约完全一致。
- 所有成功和失败响应均含 traceId、requestId 及完整统一包字段。
- 请求 ID 合法时沿用，缺失或非法时安全生成；响应头和响应体一致。
- 写请求缺失/非法幂等键、重复请求、同键异载荷、并发重复均有测试。
- 字段缺失、空白、超长、错误产品 ID、未知 JSON 字段和非法请求头均有测试。
- OpenAPI 路径、响应 schema、枚举和错误映射有契约测试。
- 日志、异常和响应不含 Key、消息正文或客户敏感数据。

## 4. 必须通过的前端检查

- `npm ci`、类型检查、单元测试和生产构建通过。
- `/xiaoming` 可直接访问和刷新；未知路由安全回到主页面。
- 使用 Pinia 和 Vue Router；产品、网络、会话、工作流、UI Store 骨架存在。
- API 客户端生成 requestId/Idempotency-Key，重试沿用原键，统一映射错误。
- 前端契约由共享 JSON 机械生成，生成检查无漂移。
- 页面按结构化数据渲染；不解析自然语言生成按钮。
- POC、隐私、固定产品和“业务能力尚未开放”提示清晰。
- 主操作满足 44px 触控、键盘焦点、语义标签、文字状态和减少动态效果。
- 375、390、430、768、1440px 无横向溢出、遮挡或布局断裂，桌面内容最大 720px。
