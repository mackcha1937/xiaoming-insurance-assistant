## 1. 已完成范围

- 健康流程按授权、输入与上传、事实确认、三态结果四步实现；未授权时不生成任何健康请求。
- 支持手工文字、可解析 PDF、JPG 和 PNG；限制一次最多 5 个、单文件 10 MB、PDF 30 页。
- 服务端校验 MIME、文件魔数、大小、数量、PDF 页数和加密状态，使用随机标识和隔离临时目录。
- 文字/PDF 提取疾病、检查、数值、日期、住院、手术、用药、复查与当前状态事实；图片 OCR 采用可替换适配器。
- OCR 未配置或失败时返回安全的手工输入提示，不猜测、不生成虚构事实，单文件失败不影响其他成功结果。
- 所有提取事实默认为未确认；编辑会取消确认，只有全部确认后才能匹配。
- 匹配只使用当前 `PUBLISHED` 健康告知和确定性规则，只输出 `HIT`、`NO_HIT_FOUND`、`INSUFFICIENT`。
- 结果包含问题编号、原因、命中事实、缺失字段、正式资料原文依据和知识版本，并固定声明不是核保或医学结论。
- 上传支持独立进度、取消、60 秒超时和同一请求标识重试；服务端拒绝同键不同内容。
- 历史只保存当前客户已确认的最小事实和结果；原始文件、完整文字、未确认事实和 `File` 对象不持久化。

## 2. 验收中发现并修复的问题

1. 健康服务存在多个构造器时 Spring 未能自动选择生产构造器；现显式标注注入构造器，并保留可替换 OCR 测试入口。
2. multipart 的未知普通参数未被只检查 Part 的逻辑发现；现同时检查参数表和 Part 名称，未知字段返回 `VALIDATION_ERROR`。
3. 通用输入过滤器曾提前读取 multipart 请求体，真实上传到控制器时内容已被消耗；现由 multipart 专用校验链处理，普通 JSON 防护不变。
4. 页面阶段数和已开放能力数曾写死为 Phase 5/7；现由当前能力契约动态计算并显示 Phase 6/8。
5. 首版浏览器持久化会保留自动提取的原始片段；现只保存确认后的最小标签或概括，来源固定为“已确认事实（原始文字未保存）”。
6. 首版失败文件重试会生成新请求标识；现为文字和每个文件保留原操作，只在失败/取消时显示同标识重试。
7. 已保存结果开始新一轮编辑时曾过早清除旧结果；现新结果成功保存前保留旧结果，撤销授权或放弃草稿可完整恢复。
8. 上传只有用户取消保护，缺少超时兜底；现增加 60 秒 XHR 超时，并沿用相同 Idempotency-Key 重试。
