# Phase 07 验收清单：正式投保外链与反馈

状态：PASS（2026-08-28）

分支：`phase/07-application-feedback`

## 1. 本阶段范围

- “开始投保前检查”汇总当前客户的规则问答、职业确认、健康确认和资料清单状态，但不强制代替正式页面校验。
- 正式投保入口只出现在快速入口、投保检查结果和资料清单完成区，不在每张回答卡重复。
- 前端必须先向后端请求安全地址，再展示外链确认弹层；确认后才新开页面，禁止浏览器自行拼接 URL。
- 确认弹层显示当前检查状态和未完成项，提供“返回检查”和“仍然进入”；取消后焦点返回发起按钮。
- 后端 `GET /api/v1/xiaoming/application-url` 基于环境配置生成地址，只接收明确允许的渠道参数。
- 基础地址必须为 HTTPS 且域名命中白名单；未知参数丢弃，健康、身份、客户备注、会话正文不得进入 URL 或响应。
- local/test、UAT 和 production 配置隔离；production 未配置或配置错误时返回 `APPLICATION_URL_NOT_CONFIGURED`，绝不回退 UAT。
- 新窗口被拦截或打开失败时保留当前页面和会话，提供同一安全地址重试或复制入口；地址带明确过期时间。
- 顾问可主动对当前问答提交“回答有误”反馈；提交前可取消，失败保留选项并沿用同一幂等标识重试。
- 反馈只保存经过白名单和脱敏的产品、意图、问题摘要、回答摘要、引用 ID、原因和匿名会话标识；默认排除健康事实。
- 受限埋点只记录事件、产品、意图、状态、耗时、知识版本和脱敏 ID，不保存完整 URL 参数或业务正文。

## 2. 明确不做

- 不代填正式投保表单，不支付，不查询或同步投保进度，不推断用户已投保、已承保或投保成功。
- 不把正式投保页当成站内页面嵌入，不绕过新窗口安全策略，不允许任意协议、任意域名或开放重定向。
- 不把姓名、身份证号、手机号、客户备注、完整对话、健康文件、健康事实或反馈中的身份内容发送到 URL、日志、指标或持久化。
- 不自动提交反馈，不默认勾选包含问题/回答内容，不以反馈替代客户支持或合规渠道。
- 不在缺失真实 UAT/生产地址时猜测地址；测试只使用保留域名或本地确定性夹具。
- 不提前执行 Phase 08 的 30—50 道业务标准题、生产发布或邀请码准入实现。

## 3. 投保前检查门禁

- 检查状态至少覆盖 `READY`、`INCOMPLETE` 和 `STALE`，分别说明可继续、未完成项和知识版本已变化。
- 未完成项按规则/职业/健康/资料清单给出可操作返回入口，不输出核保、医学或承保判断。
- 检查不收集新身份信息；只读取当前客户本机已有的结构化状态和知识版本摘要。
- 检查结果变化、客户切换、历史恢复、刷新和知识版本更新后不得复用其他客户或旧版本状态。
- 即使检查不完整也只允许顾问在明确确认后继续，确认弹层不得用误导性文案隐藏风险。

## 4. 安全外链与环境门禁

- API 请求字段、渠道名和渠道参数执行白名单；重复、空值、超长值、控制字符和未知字段安全处理。
- 生成后再次解析并校验 scheme、host、port、user-info、fragment 和规范化域名，防止开放重定向、子域欺骗和编码绕过。
- query 中只允许固定 productId 和已批准渠道键；值经过长度、字符集和 URL 编码校验。
- production 配置不得引用 UAT host；UAT 配置不得被 production profile 继承或作为默认回退。
- 缺失地址、非 HTTPS、域名不在白名单、地址含凭证/片段或配置冲突均安全停止且不返回候选 URL。
- 响应包含产品、环境、允许域名、过期时间和不代表投保成功的说明，不包含健康、客户或会话内容。
- 页面复制只复制已由后端校验的完整地址；地址过期后必须重新请求，不得继续打开缓存地址。

## 5. 反馈与埋点门禁

- `POST /api/v1/xiaoming/feedback` 使用字段白名单、长度限制、枚举、幂等键和同键不同内容冲突保护。
- 反馈默认只提交原因和引用 ID；顾问明确选择后才可附带已脱敏的问题/回答摘要。
- 手机号、身份证号、邮箱、银行卡、地址、姓名样式、URL query、健康关键词与健康意图内容被拒绝或移除。
- 反馈响应只返回随机 feedbackId、接收状态和 trace/request 标识，不回显提交正文。
- 反馈保存和埋点使用内存/可替换存储接口；测试验证日志、异常、指标标签均无高基数正文和敏感数据。
- 支持原因至少包含：依据不符、规则不符、表述不清、信息过期、其他；不得接受任意内部状态或管理员指令。

## 6. 前端与可访问性

- 正式投保卡一屏一个主动作，禁用或不可用必须同时显示原因；链接加载中按钮宽度不跳变。
- 外链确认、复制失败、地址缺失和反馈弹层覆盖成功、取消、失败、重试和返回路径。
- 新窗口拦截时不丢当前会话；复制成功只使用轻量提示，不把 URL 显示在日志或历史正文。
- 弹层具备 `role=dialog/alertdialog`、焦点锁定、Esc、背景隔离和焦点归还；触控目标不小于 44 px。
- 375、390、430、768、1440 px 无横向溢出、按钮遮挡或链接文本撑破布局；系统大字体仍可完成操作。

## 7. API、故障与回归

- OpenAPI、共享契约和 TypeScript 类型包含 application-url、feedback、错误码、卡片与动作。
- 真实 API 覆盖成功夹具、地址未配置、过期、未知参数、非法域名、production/UAT 隔离、幂等和敏感内容。
- 浏览器覆盖 READY/INCOMPLETE/STALE、确认/取消、弹窗拦截、复制、反馈提交/重试、客户 A/B 和刷新恢复。
- Phase 03 问答、Phase 04 职业、Phase 05 历史/清单和 Phase 06 健康全部回归通过。
- `.env.local`、真实地址令牌、完整 URL 参数、浏览器导出和测试临时数据不进入 Git。
