## 1. 已完成范围

- 新增当前产品、当前 PUBLISHED 知识版本下的职业搜索和精确确认 API。
- 搜索支持全半角、大小写、空白和安全同义词标准化，结合精确、前缀、包含与中文相关度排序，最多返回五项。
- 候选阶段只展示职业名称、分类路径和职业编码，不显示类别或可承保结论。
- 顾问选择候选后，服务端只按 `occupationId` 和当前知识版本精确确认，再返回类别、完整路径和职业表版本。
- 多职业输入要求分别查询；无效编码、无结果、旧版本、超时和重试均返回可恢复的安全状态。
- 前端实现 300 ms 防抖、旧请求取消、过期 `queryToken` 丢弃、3 秒超时和同幂等键重试。
- 职业确认结果只写入当前内存会话上下文；未提前实现 Phase 05 的会话持久化或动态资料清单。

## 2. 验收中发现并修复的问题

1. 职业快照测试曾污染后续 Spring 测试上下文；为集成测试增加上下文隔离，消除跨测试版本残留。
2. 前端请求 mock 的元组类型推断过窄，导致类型检查失败；改为显式请求签名后通过。
3. 新增动作和卡片类型后，旧契约断言数量未同步；已更新契约回归断言。
4. jsdom 不提供 `scrollIntoView`，曾导致页面组件测试失败；增加能力检测，不改变真实浏览器行为。
5. 首轮 240 次压测触发既有每分钟 60 次全局限流并返回 429；该轮未作为性能结论。随后保持正常限流配置，重启清空窗口并在额度内使用 50 个样本复测。
6. 确认结果标题曾显示英文 `occupationId`；已改为中文“已按职业编码精确确认”。
