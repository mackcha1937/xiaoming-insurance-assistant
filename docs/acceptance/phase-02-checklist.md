# Phase 02 验收清单：知识版本、规则与证据底座

状态：已冻结，开发中

分支：`phase/02-knowledge-rules-evidence`

## 1. 本阶段范围

- 建立产品、知识版本、源文件、页码映射、语义片段和结构化规则模型。
- 实现 DRAFT、REVIEW、PUBLISHED、DISABLED 资料状态和知识版本原子发布/回退。
- 查询强制过滤 productId、当前 PUBLISHED knowledgeVersion 和 documentType。
- 建立 BM25 与向量检索端口，使用 RRF（默认 k=60）融合，不引入额外重排模型。
- 实现向量或 BM25 单边故障的安全降级；双边故障明确停止。
- 实现 AND、OR、NOT、区间、集合、日期窗口、存在性、缺失字段和优先级规则条件树。
- EvidenceService 只从已验证片段和规则组装文件、章节、PDF/印刷页码、原文和版本。
- 无依据、依据不完整、版本不一致或规则/资料冲突时明确停止，不生成业务结论。

## 2. 明确不做

- 不启用真实 chat 回答，不调用生成模型，不把模型常识当作产品依据。
- 不实现 Phase 03 的意图编排、真实问答、依据面板交互或提示注入全链路。
- 不实现职业、历史、资料清单、健康告知和正式投保链接。
- 不导入旧车险资料到产品 36743 的知识版本。
- 没有正式资料时不得用演示文本伪造通过标准题和页码验收。

## 3. 必须由正式资料满足的输入

- 产品 36743 的正式保险条款 PDF。
- 正式投保规则/投保须知及其生效版本。
- 正式健康告知、职业分类表、投保页面/流程资料。
- 官方理赔/服务资料（若产品问答范围包含理赔路径）。
- 每份资料的来源、版本、生效时间和可发布确认。

缺少上述资料时，可以完成并自检代码底座，但 Phase 02 总结论必须为 `FAIL/BLOCKED`，
不得创建 `phase-02-passed` 标签或 Phase 03 分支。

## 4. 必须通过的自动化检查

- 状态迁移非法路径、并发发布、发布失败保持旧版本、回退和历史版本隔离。
- 文件哈希、重复文件、页码映射、印刷页缺失、页边界和语义切分。
- productId/version/type 三重过滤，不允许跨产品、旧版本或未发布资料泄漏。
- RRF 排名、双边命中、单边命中、重复片段、稳定并列和 topK 边界。
- 向量失败仅 BM25、BM25 失败仅向量且提高阈值、双失败停止。
- 规则 AND/OR/NOT、等值、集合、区间、日期、存在性、缺失字段和优先级。
- 证据完整、缺页码、缺原文、规则依据缺失、版本冲突和结果冲突。
- API schema、错误映射、日志与敏感信息扫描。
- Phase 01 的 259 项后端测试和 7 项前端测试继续通过。

## 5. 正式资料验收

- 对 30—50 道标准题执行关键词和口语改写检索回归。
- 每个关键结论可追溯到产品、版本、文件、章节、PDF 页、印刷页、片段和规则 ID。
- 规则数字与正式原文一致；冲突题 100% 停止，旧版本 100% 隔离。
- 页码抽样逐页核对，表格语义不丢失，资料优先级符合开发文档。

任一必测项失败，或正式资料未到位，Phase 02 不得验收为 `PASS`。
