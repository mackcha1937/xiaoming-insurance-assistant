# Phase 04 验收清单：职业查询

状态：已完成，`PASS`

分支：`phase/04-occupation`

## 1. 本阶段范围

- 在当前产品 36743 的 PUBLISHED 知识快照中查询职业，职业表必须携带知识版本和职业版本。
- 对输入执行全半角、大小写、空白和安全同义词标准化，不改变职业风险含义。
- 结合精确、前缀、包含和中文分词相关度生成候选，最多返回五项。
- 候选阶段只返回职业名称、分类路径和 `occupationId`，不得提前显示类别或可承保结论。
- 顾问明确选择候选后，确认接口只按 `occupationId` 在当前版本执行精确查询。
- 确认命中后显示职业编码、类别、完整分类路径、职业表版本和边界提示。
- 支持信息不足继续补充、都不是、重新查询、确认未命中和多职业分别查询。
- 前端实现 300 ms 防抖、`AbortController` 取消、`queryToken` 过期响应丢弃和 3 秒超时。

## 2. 明确不做

- 不使用职业名称或自由文本直接输出最终职业类别或可承保结论。
- 不自行推断多个职业的合并风险，也不在正式资料未规定时采用“就高”原则。
- 不把职业搜索交给 DeepSeek，不发送职业表或用户输入到外部模型。
- 不提前实现会话持久化、动态资料清单、健康告知或正式投保外链。
- 不宣称保险公司最终承保；确认结果仍以正式投保页面和保险公司审核为准。

## 3. 后端必须通过

- 当前正式职业表 1,546 条、`occupationId` 唯一、类别仅 1—4 类、职业版本一致。
- 精确、别名、工作内容、多候选、少于/等于五项和零候选测试通过。
- 过短或模糊描述返回继续补充；多职业提示分别查询，不合并判断。
- 候选响应不包含类别、可承保布尔值或结论；确认前不能绕过人工选择。
- 确认请求不接受名称、类别、路径等客户端结论字段；未知字段必须拒绝。
- 确认命中严格使用当前版本中的 `occupationId`；无效 ID 返回明确未命中。
- 搜索后知识版本变化时，旧版本确认必须停止并要求重新查询。
- 无发布快照、职业表为空、产品错误、版本冲突、超时和幂等冲突有明确安全结果。
- 多次代表性搜索的 P95 小于 2 秒，并记录测量样本、结果和运行环境。

## 4. 前端必须通过

- 职业查询成为第六项已开放能力；其他三项仍保持禁用。
- 点击职业查询打开独立职业面板，不把自由文本直接作为最终判断。
- 搜索输入 300 ms 防抖；新查询取消旧请求，过期 `queryToken` 响应不得覆盖新结果。
- 候选使用单选列表；未选择时“确认职业”禁用；候选最多五项且不显示类别。
- “都不是”打开工作内容补充区；“重新查询”保留原描述供修改。
- 确认结果展示职业编码、类别、路径、版本和非承保承诺提示。
- 空输入、加载、无候选、补充信息、成功、失败、超时、取消和同键重试状态可恢复。
- 375、390、430、768、1440 px 无溢出、遮挡或不可达操作；键盘、焦点、语义标签、
  `aria-live`、触控尺寸和 reduced-motion 检查通过。

## 5. 安全与回归

- 职业输入、完整请求正文和候选内容不写入应用日志；前端控制台不打印请求正文。
- `.env.local`、DeepSeek Key、正式原始职业表和本地数据不进入 Git。
- Phase 03 五类问答、提示注入、混合问题、证据门禁和无登录 POC 边界继续通过。
- `scripts/phase-gate.sh`、职业 API E2E、浏览器测试、性能测试和阶段范围审计全部通过。

## 6. 阶段退出条件

- 确认前不判断；确认后只按当前版本精确查询。
- 别名、多候选、未命中、多职业、版本冲突、超时和重试全部通过。
- 职业搜索 P95 目标可复现且小于 2 秒。
- 生成 `docs/acceptance/phase-04-report.md`，结论为 `PASS` 后才允许提交、创建
  `phase-04-passed` 标签和 Phase 05 分支。
